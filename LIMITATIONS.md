# Limitations

What this project does **not** do. Written so that nobody downstream — including a future
version of us — mistakes a capability of the framework for a capability of the result.

## The headline

The simulation, data loading, plasticity machinery, experiment harness, metrics and CLI are
verified end-to-end (200 tests). **Learning is not demonstrated.** In 18 configurations of the
reward-modulated rule on two tasks, held-out accuracy never crossed chance plus 5 points
(`EXPERIMENTS.md` has the table). Nothing in this repo supports the phrase "digital fruit fly"
and nothing supports "learns Luau".

## Data

- **The loader has never seen a real FAFB file.** `fruitfly/dataset/loader.py` is validated
  against synthetic TSV/CSV.gz files written to the published v783 schema
  (`data/sample/fafb_v783/`, generated by `fruitfly.dataset.build_sample`). Column names,
  row counts and value ranges in `DATA.md` are transcribed from FlyWire documentation, not
  measured here: the sandbox has no egress to the Codex/Zenodo archives. The first thing to
  do on a machine that has the files is `python scripts/inspect_fafb.py --dir <path>` and
  compare against `DATA.md`. A real file with a different header (e.g. `pre_pt_root_id`
  instead of `pre_root_id`) is the most likely first failure, and the loader should get
  aliases rather than a reindexed copy.
- **Connectivity is at "neuron pair + synapse count" resolution.** No per-synapse location,
  no section-level compartment structure, no physical distance along neurites, no
  neurotransmitter quantal size. Synaptic delay is a single scalar per edge, not a function
  of axonal path length. Consequently nothing here can express compartmental computation,
  which is where a real fly neuron does much of its work.
- **Weights are synapse counts with `log1p` applied** — a proxy for connection strength, not
  a measurement of conductance.
- **`neuropil` labels and cell types come from a different table** than the connections, with
  different id cardinality (`labels.csv.gz` has 160,045 rows but 110,038 unique ids;
  `coordinates.csv.gz` is marked as a subset). Selections that look up annotations can
  legitimately find nothing for a given root id; the code raises with a message rather than
  silently narrowing the population.
- **Skeleton coordinates are in microns; synapse coordinates are in nanometres.** Mixing them
  up is a 1000x error. Only the skeleton table is used (for a scatter plot), and it is
  optional.
- Sampled subgraphs are **not** the whole fly: `tiny` is 100 neurons out of 139,255 (0.07%).
  Statistics computed on a subgraph do not describe the brain.

## Simulation

- **LIF, not multicompartment Hodgkin-Huxley.** One state variable per neuron (`v`), plus a
  trace for eligibility. No dendrites, no active conductances, no calcium dynamics, no
  glia, no vasculature, no neuromodulator diffusion (reward is a global scalar).
- **Fixed 0.5 ms step, no adaptive integration.** Events are snapped to the grid; with
  `tau_syn_ms = 2.0` this is adequate but not precise, and thin spike-timing windows
  (a few ms) are only coarsely represented.
- **Inhibition is present but coarse**: `ei_mode: nt` signs an edge from a predicted
  transmitter label (`GABA`→inhibitory, empty label defaults to excitatory). Predictions are
  imperfect for 19,658 of 139,255 neurons, and the sign of a mixed input is not modelled.
- **Homeostasis is a clamp, not a mechanism.** `normalize: colsum` rescales incoming weight
  columns after each trial to keep total conductance fixed. This is arithmetic, not biology,
  and it is the single most consequential cheat in the model — it forces competition between
  presynaptic axons rather than letting it emerge.
- **No plasticity at all is available for `plastic_targets: all` at scale without the network
  saturating.** We measured both regimes; neither yields learning. See `EXPERIMENTS.md`.

## Readout and learning

- **The readout is a linear group-rate classifier fit outside the network**
  (`fruitfly/experiment/readout.py`). It is re-fit at each evaluation. So "the network learned"
  can never mean more than "the network's activity became linearly more separable under this
  fixed decoder". A frozen readout across a run — which is what a behaviourally-animal
  experiment implies — is not implemented.
- **Chance-level performance is not a floor on this data structure.** With 2-4 stimuli, the
  untrained network can sit at 1.000 or at 0.021 on held-out data depending on which
  permutation of the class→neuron-group mapping is chosen. `counterbalance_init: true` exists
  to remove that freedom (start at the worst mapping) and the criterion additionally refuses to
  count a gain when the untrained baseline is already above chance. Both were added after
  seeing the failure modes, not before.
- **exp001/exp002/exp004/exp005(modulus 3) have exhaustive input spaces.** Their "held-out"
  split contains every possible stimulus; those runs measure associative learning, and any
  accuracy figure from them is **not** a generalisation result.
- **`|dW| > 0` is a mechanism check, not a learning check.** The tables in `EXPERIMENTS.md`
  contain rows with |dW| in the millions and an accuracy change of exactly zero.
- Statistical testing is a one-sided exact binomial against chance on the eval trial count
  (default 48). No multiple-comparison correction across the sweep grid: with 18 runs, one
  p<0.05 by luck is plausible. Treat any single passing row from a sweep as a candidate to
  replicate, not a result.

## Luau

`fruitfly/luau/` contains a total tokenizer, task construction, static checks and a
`TestCase` data model. **It cannot execute Luau.** `evaluator.execute()` returns a
"no backend" outcome on every input; it never runs code — the static scan is not an
interpreter and does not pretend to be. `LIMITATIONS` for that subproject: even with a real
Luau backend, nothing in phases 1-6 consumes tokens, so there is no measured path from
"connectome simulation" to "code completion". The claim "toward learning Luau" in the repo
description is a direction of travel, not a status.

## Engineering honesty

- `config/default.yaml` is the calibration of record; **the calibration sweep
  (`scripts/calibrate_dynamics.py`) selected on activity statistics, not on task
  performance.** It guarantees the network is neither silent nor saturated. It does not
  guarantee learnability.
- Reproducibility is real for CPU numpy/scipy code paths: seeded, `config_hash` recorded in
  `setup.json`, weights in `.npz` checkpoints. It is **not** guaranteed across BLAS
  implementations for the large sparse products; bit-exactness on a different machine is not
  claimed (metrics agree to ~1e-12 in our checks, which is not the same thing).
- `runs/` output is machine-local and git-ignored, by design — the repo carries the
  configuration and the analysis scripts, and the numbers in the docs were produced by the
  commands written next to them. If you cannot reproduce a number in `EXPERIMENTS.md`, that is
  a bug; please file it.
- matplotlib is optional. Everything except the figures runs without it.
