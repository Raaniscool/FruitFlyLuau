# FruitFlyLuau

A connectome-grounded spiking neural network built on the **FlyWire FAFB v783**
*Drosophila* wiring diagram, driven by an open-ended task curriculum with
reward-modulated synaptic plasticity. The long-term question: **how far can a
brain-derived network be pushed toward learning to write Luau (Roblox) code?**

**Current status, stated plainly:**

| | |
|---|---|
| FAFB v783 loader | implemented; validated against **synthetic files built to the published schema**, not yet against your local download (see [DATA.md](DATA.md)) |
| Connectome → simulation | real sampled subgraph, vectorised LIF over CSR, deterministic per seed |
| Plasticity | STDP / reward-modulated STDP / Hebbian trace / frozen, all tested |
| Experiments 001–005 | runnable end-to-end with pre/post held-out evaluation, checkpoints, controls |
| **Learning demonstrated?** | **No.** Every configuration measured so far is a null result. See [EXPERIMENTS.md](EXPERIMENTS.md) for the numbers and the diagnosis. |
| Luau generation | **not implemented.** Only a tested tokenizer, a task schema, and a sandbox contract that refuses to execute anything |

This repository makes no claim that a fly brain has been simulated, emulated, or
reproduced. It is a computational abstraction of a wiring diagram, and where the
system falls short of its ambition that is written down rather than smoothed over.
See [LIMITATIONS.md](LIMITATIONS.md).

## Quickstart (works with no data download)

```bash
pip install -e ".[dev]"

python -m fruitfly doctor          # what this machine can see
python -m fruitfly rules           # registered rules / encoders / decoders / selections
python -m fruitfly stats --data-dir data/sample/fafb_v783 --mode tiny --neurons 120
python -m fruitfly sim   --data-dir data/sample/fafb_v783 --mode tiny --neurons 120 --steps 200
python -m fruitfly run   --config config/experiments/exp001_binary_sample.yaml --plot
python -m pytest -q                # 200 tests
```

`data/sample/fafb_v783/` is **synthetic**: 86 KB of files whose names and column
headers match the real FAFB v783 assets, generated by
`fruitfly.dataset.build_sample`. It exists so the pipeline is testable offline and
so CI does not need a 68 MB download. Nothing in it is real connectomics data.

## Using the real connectome

1. Download the FAFB v783 assets you want (start with `connections_princeton.csv.gz`,
   68 MB, and `neurons.csv.gz`) — [DATA.md](DATA.md) has the full table, the Codex
   endpoints and the mirrors.
2. Point the project at them: `export FAFB_DATA_PATH=/path/to/FAFB_v783` (Windows
   PowerShell: `Set-Item -Path Env:FAFB_DATA_PATH -Value "$env:USERPROFILE\Downloads"`).
3. **Before trusting any number, validate the loader against your actual bytes:**

```bash
python scripts/inspect_fafb.py --dir "$env:FAFB_DATA_PATH" --count-rows --write-profile
# or, for the full audit (duplicate pairs, reciprocity, exact counts; slower, more RAM):
python scripts/inspect_fafb.py --dir "$env:FAFB_DATA_PATH" --deep --write-profile
```

   It writes an 18-section audit — inventory, sizes, formats, row counts, per-column
   inferred types and missing-value rates, example rows, unique-ID statistics,
   cross-file ID compatibility, connection- and synapse-table structure, cell-type,
   visual and neurotransmitter annotation structure, schema hazards, a recommended
   canonical internal schema, and which files the first experiment needs versus which
   stay lazy-loaded. Anything it cannot establish from the bytes is written as
   `UNKNOWN -- requires further investigation` rather than guessed.
   That script needs nothing but the Python standard library, so it runs on a plain
   Windows install. It writes `fafb_schema_report.md` / `.json`; commit them (or paste
   them into an issue) and the loader's column aliases and row counts get checked
   against reality instead of against documentation. If your export uses different
   column names, add `--write-profile`: it emits `config/fafb_profile.yaml`, which the
   loader then prefers over its built-in aliases — no code edit needed.
4. `python -m fruitfly stats --mode small` then `python -m fruitfly run -e exp003_pattern ...`.

## Layout

```
fruitfly/dataset/     FAFB asset registry, discovery, schema aliasing, chunked loader, synthetic sample
fruitfly/graph/       CSR connectome, population selection (upstream/downstream/hubs/annotation), scales
fruitfly/neuro/       vectorised LIF over the sparse graph + plasticity rules
fruitfly/learning/    reward ledger, dopamine-like modulatory trace
fruitfly/io/          spike encoders (input) and readout decoders (behaviour)
fruitfly/experiment/  task environments, metrics, checkpoints, runner, readout-mapping counterbalance
fruitfly/viz/         figures (matplotlib optional)
fruitfly/luau/        phase 7/8 scaffold: tokenizer + task schema + sandbox contract (refuses to execute)
fruitfly/cli/         doctor / sample / inspect / stats / sim / run / rules
config/default.yaml   every tunable; layer config/local.yaml or --set section.key=value over it
config/experiments/   the two configurations the numbers in EXPERIMENTS.md came from
scripts/              calibrate_dynamics.py, inspect_fafb.py (stdlib-only)
tests/                200 tests, no data download required
```
